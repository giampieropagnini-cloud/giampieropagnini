# Automating fashion pattern-making (Lectra Modaris tasks) with code and AI, state as of October 2026

Research note for the report writer. Scope: what a non-expert plus an AI coding assistant could realistically build in Python/JavaScript to replace or speed up Modaris-type work (parametric drafting, grading, seam allowances and notches, DXF-AAMA/ASTM export, tiled PDF, nesting/marker making, fabric consumption, tech packs, AI garment generation, 3D preview), and where the limits are.

Method caveat: many primary sites were blocked by this environment's network proxy (arxiv.org, freesewing.eu, support.clo3d.com, developer.clo3d.com, minervapatterns.com, mpattern.app, normsplash ASTM sample, Patro docs, theinterline.com, newswire.ca). For those, findings come from search-engine result snippets attributed to that URL, not from a full read. GitHub pages could be fetched and were read directly. Vendor blogs (Style3D, fashionINSTA, thefword.ai, iFactory, Apex Fashion Lab) are marketing; their claims are flagged.

## 1. Parametric / programmatic pattern drafting: what exists and how it is coded

### Takeaway
Parametric drafting from body measurements is a solved, open-source problem at "basic block plus variations" level. FreeSewing (JavaScript, MIT) and GarmentCode/pygarment (Python, MIT, ETH Zurich) are mature code-first frameworks. Seamly2D/Valentina (GUI with formulas) and the commercial GRAFIS (which embeds the Müller & Sohn system) show that a classical drafting method such as Aldrich, Müller & Sohn, Secoli or Burgo can be written as a sequence of measurement-driven construction steps. No open-source code implementing the Italian methods (Secoli, Burgo) was found. They would have to be encoded by hand from the textbooks.

### Cited Findings
- **FreeSewing** is "a JavaScript library for parametric design with a focus on sewing patterns". The core is published on npm as `@freesewing/core`. Its `Pattern` object is "the parametric blueprint that when instantiated with a user's settings can draft a bespoke sewing pattern". The user's measurements are taken into account when drafting. — [FreeSewing Pattern API](https://freesewing.dev/reference/api/pattern/); [Core API](https://freesewing.dev/reference/api/); [Adding measurements tutorial](https://freesewing.dev/tutorials/pattern-design/part2/adding-measurements/)
- FreeSewing export formats include A4 PDF tiled to A4 pages, A3/A2/A1/A0 PDF, and Letter/Legal/Tabloid PDF, each tiled to its paper size. — [FreeSewing Editor docs](https://freesewing.eu/docs/editor/) (search snippet)
- FreeSewing is MIT-licensed. v4 was released 1 April 2025 and requires NodeJS 20+. 2025 releases added designs: Sabrina sports bra (v4.1), Devon denim jacket plus Sarah and Sunny skirts (v4.2, August), Percy pants (v4.3, September), Sophie slip dress (v4.4, 6 November 2025). — [Announcing FreeSewing v4](https://freesewing.eu/blog/announcing-v4); [2025 Autumn newsletter](https://freesewing.eu/newsletter/2025q4) (search snippets)
- **GarmentCode** (Maria Korosteleva, ETH Zurich) is "a modular programming framework for designing parametric sewing patterns", MIT license. Its core library **pygarment** contains base types `Edge`, `Panel`, `Component` and `Interface`, plus an edge factory and helpers/operators for building patterns. v2.0.0 (30 Aug 2024) added a new GUI and JSON representation classes. An online configurator went live 20 Nov 2024 at garmentcode.ethz.ch and was relaunched 3 June 2025. — [GarmentCode GitHub](https://github.com/maria-korosteleva/GarmentCode); [pygarment on Libraries.io](https://libraries.io/pypi/pygarment)
- GarmentCode body measurements come from files in `./assets/body_measurements`, with presets such as `neutral`, `mean_female`, `mean_male`, `f_smpl`, `m_smpl`. A local web GUI (`python gui.py`) shows the sewing pattern and draped 3D models. Patterns are serialized as JSON (`pattern_specification.json`) for simulation. — [GarmentCode docs: Running_garmentcode](https://github.com/maria-korosteleva/GarmentCode/blob/main/docs/Running_garmentcode.md)
- **GarmentCodeData** is a synthetic dataset of 115,000 made-to-measure 3D garments with sewing patterns: tops, shirts, dresses, jumpsuits, skirts, pants, etc., fitted to varied body shapes in three fabric materials. It was accepted at ECCV 2024. — [GarmentCodeData project page](https://igl.ethz.ch/projects/GarmentCodeData/); [GarmentCode GitHub](https://github.com/maria-korosteleva/GarmentCode)
- **Seamly2D / Valentina** (open-source, GUI) create patterns from either multisize size tables (`.vst`) or individual measurements, using formulas. — [Valentina (Wikipedia)](https://en.wikipedia.org/wiki/Valentina_(software)); [Seamly forum: Grading/Multi-size](https://forum.seamly.io/t/grading-multi-size-in-seamly-2d/5789)
- **GRAFIS** (commercial, German) is interactive pattern CAD in which "each step is documented in a construction record and can be utilized again with different measurement charts". It embeds the M. Müller & Sohn system. The site says that system is the most widely used in the international clothing industry and needs only 15 measurements for menswear, deriving secondary measurements with formulas. — [GRAFIS clothing](https://www.grafis.com/clothing); [Pattern Support: Maßsysteme](https://www.pattern-support.at/grafissoftware/cad-bekleidung/ma%C3%9Fsysteme/)
- Italian methods: the Secoli method is taught by Istituto Secoli (Milan) for industrial pattern construction. Burgo's "Il Modellismo" has a section on size development (sviluppo taglie). An Italian online academy sells a course on parametric models in Valentina CAD for developing size tables. — [Secoli modellistica courses](https://secoli.com/corsi/modellistica/); [Burgo, Il Modellismo (Amazon.it)](https://www.amazon.it/modellismo-sartoriale-industriale-bambino-italiana/dp/8890010150); [Fastweb Digital Academy – Valentina modelli parametrici](https://www.fastwebdigital.academy/corsi-online/digital-design-making-online/modelli-parametrici)
- Istituto Secoli also teaches Lectra Modaris Expert, currently version V2025.2. — [Secoli Modaris Expert course](https://secoli.com/en/fashion-courses/online-courses/modaris-expert-lectra-cad-pattern-making/)

### Inferences
- A drafting system such as Aldrich's "Metric Pattern Cutting" bodice, Müller & Sohn or Secoli maps directly to code. Each construction step ("point B = A + bust/4 + 1 cm ease") becomes a named point computed from measurements, and curves become Bézier or spline segments between points. This is exactly how FreeSewing parts and GarmentCode panels are written. An AI assistant can transcribe a textbook draft into such code quickly. The bottleneck is the precise formulas and ease values from the book, which must come from the niece's course material (copyrighted texts, not open data).
- For an Italian student, a sensible path is to encode her school's method (likely Secoli or Burgo-style) for 3–5 basic blocks (bodice, skirt, trousers, sleeve, maybe shirt). That gives patterns that match what her teachers expect, which matters more than adopting FreeSewing's own block shapes.
- GarmentCode is tuned for research and simulation (3D draping, datasets). FreeSewing is tuned for printable home-sewing patterns with production details such as seam allowance and print layout. For "professional 2D output" FreeSewing's model is closer. For "AI + 3D" GarmentCode is the hub everything else plugs into (see question 5).

### Gaps
- Not verified whether GarmentCode natively exports SVG/PDF/DXF or supports seam allowances. The docs read did not mention it.
- No open-source implementation of Secoli, Burgo, Lutterloh or Müller & Sohn formulas was found. The Müller & Sohn system exists in code only inside commercial GRAFIS.
- FreeSewing's plugin list (seam allowance, notches, grainline, cut-on-fold) could not be confirmed from freesewing.dev because the domain was blocked for full fetch.

## 2. Grading automation (sviluppo taglie): grade rules vs measurement-driven made-to-measure

### Takeaway
Industrial grading in Modaris and AccuMark is "grade-point" grading. Selected points on the base-size pattern carry a rule: an x/y movement per size step, stored in a rule table (`.RUL`). Computing this in code is simple vector arithmetic. The hard part is the know-how in choosing the rules (the brand's size chart and grading increments). The alternative is to re-draft every size from its own row of a measurement table. FreeSewing, Seamly2D and GRAFIS do this, and it removes manual grading altogether. With code, this measurement-driven approach is the natural choice.

### Cited Findings
- A grade rule is "a set of numbers… amounts of movement. Each number indicates how much (and in which direction) a given point moves between two adjacent sizes". A grade rule is the collection of these movements for each point and size along the X and Y axes. — [Alison Hoenes: Size charts, spec charts and grade rules](https://alisonhoenes.com/2021/02/size-charts-spec-charts-and-grade-rules-what-they-are-for-and-how-theyre-different/) (search snippet)
- A `.rul` file holds the list of sizes, the base size, and relative movement vectors for each grade point. RUL files come from CAD such as Lectra Modaris, Gerber AccuMark and Optitex. — [Gerber Technology Community: rul and dxf files](https://gerbertechnology.vanillacommunity.com/discussion/2267/rul-and-dxf-files); [convert.guru RUL converter](https://convert.guru/rul-converter) (search snippets)
- AccuMark grading methods include **Small-Large Incremental** (grade from smallest to largest, rule value = grade between sizes) and **Base Up-Down Incremental** (grade from base up and down to the next size break). — [Gerber AccuMark help: Grade Options](http://help.gerbertechnology.com/accumark/pds/Function_Grade_Options.htm); [Assign Rule Table](https://help.gerbertechnology.com/AccuMark/PDS/Function_Assign_Rule_Table.htm)
- AAMA/ASTM DXF has a dedicated layer for **grade reference lines** (layer 5), and each boundary vertex carries a code identifying it as a curve point, corner, notch or grade reference. This is how grade points travel with the geometry. — search summary of [Autodesk forum: export to DXF AAMA/ASTM](https://forums.autodesk.com/t5/autocad-forum/autocad-export-to-dxf-aama-or-dxf-astm/td-p/7014285) and related pages (secondary)
- Seamly2D supports multisize tables but **cannot export a multi-size (graded nest) pattern as a single file**. Each size must be exported separately. — [Seamly2D and open-source pattern CAD (Minerva)](https://minervapatterns.com/blog/seamly2d-and-open-source-pattern-cad-a-practical-look) (search snippet); [FashionFreedom discussion #1199](https://github.com/orgs/FashionFreedom/discussions/1199)
- GRAFIS: a pattern design created once can be repeated for each size from measurement charts, supporting both standard-size grading and made-to-measure. — [GRAFIS clothing](https://www.grafis.com/clothing)

### Inferences
- In code, grade-point grading is: `P(size_k) = P(base) + Σ_{steps from base to k} (dx_i, dy_i)` for each rule-carrying point. Non-grade points are interpolated along the curve between graded points, typically by proportional arc length. An AI assistant can implement this, plus a nested-size "stack" plot, in a day or two.
- Measurement-driven re-drafting (run the parametric draft once per size row) is easier to build and gives smoother results. However, industry partners such as factories and Modaris users expect a graded nest and often a RUL table. To interoperate, the tool can compute per-point x/y deltas *after* drafting each size (diff each size against the base) and write them out as grade rules. That converts made-to-measure output into standard grading data.
- The quality of grading depends on the size chart and the increments (for example 4 cm bust per size, 0.5 cm shoulder), which are brand-specific know-how. Code does not supply them.

### Gaps
- The exact ASCII syntax of the AAMA/ASTM `.RUL` grade-rule file was not retrieved (ASTM D6673 is paywalled and was withdrawn in 2019 per iTeh; the sample PDF was blocked). It needs checking against a real Modaris/AccuMark export before writing a RUL writer.
- No open-source RUL reader/writer library was found.

## 3. File formats: DXF-AAMA / ASTM D6673, ezdxf, CAD interoperability, tiled PDF and plotter output

### Takeaway
DXF-AAMA/ASTM is ordinary DXF with conventions: one BLOCK per pattern piece, fixed numbered layers for cut line, notches, grain, internal lines, sew line, drill holes and text, plus an optional `.RUL` grading file. Python can write it with ezdxf, which even ships a `gerber_D6673` export add-on. Expect trial and error against each target CAD's picky importer. CLO3D and Valentina import/export AAMA. Lectra and Gerber accept AAMA/ASTM, but each has quirks. Tiled A4 PDF and A0 plotter PDF are easy (FreeSewing does it natively, and PDFStitcher handles tiles and layers).

### Cited Findings
- ASTM D6673 ("Standard Practice for Sewn Products Pattern Data Interchange—Data Format") defines a DXF-compliant format. Version D6673-10 is listed as **withdrawn 2019**. — [iTeh: ASTM D6673-10](https://standards.iteh.ai/catalog/standards/astm/3ea6d7eb-457d-4601-8b2a-568fe262a910/astm-d6673-10)
- ASTM uses **one DXF block per pattern piece** containing graphic and text information. Detail information is assigned to one of 23 predefined layers. AAMA and ASTM describe the same idea but assign features to **different layer numbers and use point codes differently**. — [Patro docs: DXF ASTM](https://fabricesalvaire.github.io/Patro/resources/file-format/dxf-astm.html); [Minerva: DXF AAMA vs ASTM](https://minervapatterns.com/blog/dxf-aama-vs-dxf-astm) (search snippets)
- AAMA layer conventions reported by secondary sources (verify against a real file): 1 boundary/cut line; 2 turn points; 3 curve points; 4 notches; 5 grade reference lines; 6 mirror line; 7 grain line; 8 internal lines; 9 stripe reference; 10 plaid reference; 11 internal cut-outs; 13 drill holes; 14 sew lines; 15 second drill holes or annotation (sources differ); 19 text. — search summaries citing [Autodesk forum thread](https://forums.autodesk.com/t5/autocad-forum/autocad-export-to-dxf-aama-or-dxf-astm/td-p/7014285), [McNeel forum: export for Modaris](https://discourse.mcneel.com/t/export-file-for-modaris-lectra-need-dxf-aama-or-astm/9708), [i-digit: DXF import/export problems](https://www.i-digit.co.uk/post/dxf-import-export-problems). The layer 12 and 15 meanings were inconsistent across sources.
- **ezdxf** (Python) can read/write DXF and has an add-on `ezdxf.addons.gerber_D6673` (`gerber_D6673.export_file(doc, "output.dxf")`) that writes ASTM-D6673-10 files usable by Gerber AccuMark. The maintainer notes that core ezdxf "does not fully support" ASTM structures. Standard DXF requires modelspace/paperspace layouts, which conflicts with what Gerber expects. He says "Gerber Technology applications just have low-quality DXF parsers": add-on output fails Autodesk TrueView validation yet works in Gerber. — [ezdxf discussion #789](https://github.com/mozman/ezdxf/discussions/789); see also [ezdxf discussion #838](https://github.com/mozman/ezdxf/discussions/838)
- **Valentina** supports DXF AAMA/ASTM export (for CLO3D). **Seamly2D** supports AAMA/AutoCAD DXF (e.g., "AutoCAD DXF 2013 AAMA") but has **no native ASTM**. — [Valentina (Wikipedia)](https://en.wikipedia.org/wiki/Valentina_(software)); [seamly2d man page](https://manpages.debian.org/experimental/seamly2d/seamly2d.1.en.html); [Minerva Seamly2D article](https://minervapatterns.com/blog/seamly2d-and-open-source-pattern-cad-a-practical-look) (snippets)
- CLO3D documents 2D pattern DXF import/export. — [CLO support: 2D Pattern (DXF) Import/Export](https://support.clo3d.com/hc/en-us/articles/115000493067-2D-Pattern-DXF-Import-Export) (page blocked; existence confirmed by search)
- Lectra positions interoperability between Gerber AccuMark and Lectra Modaris as a feature (Lectra now owns Gerber). — [Lectra: patternmaking solution interoperability](https://www.lectra.com/en/library/achieve-a-seamless-workflow-with-patternmaking-solution-interoperability)
- Tiled PDF: FreeSewing exports PDF tiled to A4/Letter and also A3–A0. — [FreeSewing Editor docs](https://freesewing.eu/docs/editor/) (snippet). **PDFStitcher** (open source, MPL-2.0, Python, `pip install pdfstitcher`) stitches tiled sewing-pattern PDFs into one large page, keeps and filters PDF layers (OCGs), changes line properties per layer, and supports margins, trim and overlap. It was described in an ACM DocEng 2022 paper by Charlotte Curtis. — [sewingutils / PDFStitcher GitHub](https://github.com/Quinn-D/sewingutils); [ACM paper](https://dl.acm.org/doi/pdf/10.1145/3558100.3563853); [PyPI pdfstitcher](https://pypi.org/project/pdfstitcher/0.5.4/)
- A freelancer guide on ASTM ePatterns exists (DH Patterns and Fit). — [ePattern ASTM Standard PDF](https://dorthehansen.com/wp-content/uploads/2014/10/ePattern-ASTM-Standard.pdf) (not read)

### Inferences
- A writer for AAMA DXF in Python is about 300–600 lines with ezdxf. It creates a BLOCK per piece with a boundary polyline on layer 1, notches as short lines on layer 4, a grain line on layer 7, internal lines on layer 8, sew line on layer 14, TEXT for piece name/size/quantity, then an INSERT for each block. The real effort is iterating with the target system's importer. Get one reference AAMA file exported from Modaris at the university and mirror its exact structure (layer names, header, units, text tags such as "Piece Name:", "Size:", "Quantity:").
- Practical compatibility expectation: CLO3D and Valentina/Seamly2D are forgiving. Modaris and AccuMark import AAMA/ASTM but may drop notch types, grading or annotations if conventions differ. Graded multi-size DXF plus RUL import into Modaris is the hardest part and should be considered unproven until tested.
- Home-print PDF: generate the pattern at 1:1 as SVG or PDF vector, then tile with overlap, registration marks, a 10 cm test square and a page grid (A1, A2…). This is a small task with reportlab, pypdf or cairo, or reuse FreeSewing's tiler. A0 plotter output is the same vector drawing on a single 841×1189 mm page or a roll width (e.g., 914 mm), with no tiling.

### Gaps
- Could not read the full layer table from the ASTM spec or Patro docs (blocked). The layer numbers above come from secondary or AI-summarized snippets and need verification against a real file.
- No first-hand evidence that a Python-generated AAMA file imports cleanly into **Lectra Modaris** specifically. This needs a test at the university.
- Lectra's own DXF import documentation was not accessible.

## 4. Nesting / marker making (piazzamento) and fabric consumption

### Takeaway
Open-source nesting has improved sharply. **sparrow** (KU Leuven, Rust, MIT, 2025) reports best-known densities on academic benchmarks that include real garment instances (shirts, trousers, swim, albano, dagli), with a Python wrapper (`spyrrow`). Deepnest (genetic algorithm plus no-fit polygon) and libnest2d/pynest2d are older, easier options. With apparel constraints added in code (grain direction, rotations only 0/180, flips, size-quantity ratios, fabric width), a script can produce usable markers and consumption estimates. Commercial auto-nesters (Lectra Diamino, Gerber AccuNest) still win on integration, plaid/stripe matching, cutter output and validated results. Industry target efficiency is about 80–90%.

### Cited Findings
- **sparrow**: "State-of-the-art nesting for 2D irregular strip packing", Rust, MIT, built on the **jagua-rs** collision-detection engine. It accepts JSON input, and SVG/DXF via the browser app sparrowstudio.app. It supports discrete, stepped or continuous rotation per item, uses an exploration phase (80% of time) then a compression phase (20%), has a default 600 s time limit, supports warm-start, and has a Python wrapper `spyrrow`. Benchmark instances include **shirts, trousers, swim, albano, dagli, mao, marques, jakobs, fu**. — [sparrow GitHub](https://github.com/JeroenGar/sparrow); [sparrow experiments](https://github.com/JeroenGar/sparrow/tree/main/data/experiments); [jagua-rs GitHub](https://github.com/JeroenGar/jagua-rs)
- Paper: "An open-source heuristic to reboot 2D nesting research" (Gardeyn, Vanden Berghe, Wauters, KU Leuven, arXiv 2509.13329, Sept 2025). It decomposes the problem into a sequence of feasibility problems that gradually resolve collisions and "consistently outperforms the state of the art — in some cases by an unexpectedly wide margin". Example: ALBANO density 89.47% vs 87.55% (ROMA) and 87.47% (GCS). — [arXiv 2509.13329](https://arxiv.org/abs/2509.13329) (snippet); [ResearchGate](https://www.researchgate.net/publication/395583530_An_open-source_heuristic_to_reboot_2D_nesting_research)
- **Deepnest** (open source, CNC/laser oriented) uses a genetic algorithm plus no-fit polygon (NFP) computation, with NFP caching and parallel workers. The active community fork is deepnest-next. — [deepnest-next GitHub](https://github.com/deepnest-next/deepnest); [DeepWiki nesting algorithm](https://deepwiki.com/deepnest-next/deepnest/5.1-nesting-algorithm); [Jack000/Deepnest](https://github.com/Jack000/Deepnest/blob/master/main/readme.md)
- **pynest2d**: CPython bindings for libnest2d (2D polygon packing), maintained by Ultimaker for Cura, LGPL (a competing binding is AGPL). It is packaged in Ubuntu 24.04. — [Ultimaker/pynest2d](https://github.com/Ultimaker/pynest2d); [Launchpad python3-pynest2d](https://launchpad.net/ubuntu/noble/+package/python3-pynest2d)
- AI/RL nesting research continues, e.g., "Geometry-Aware Reinforcement Learning for 2D Irregular Nesting" (arXiv 2606.10611, June 2026). This is research, not a product. — [arXiv 2606.10611](https://arxiv.org/pdf/2606.10611) (not read)
- **Gerber AccuNest** (vendor): analyses multiple nesting solutions and delivers the highest utilization. It claims "up to 1 percent" better utilization than single-core systems and Multi-Core "up to 2 percent". — [Gerber AccuNest PDF](https://www.gerbertechnology.com/pdf/accunest_e.pdf); [AccuNest page](https://gerbertechnology.com/technical-textiles/nesting/accunest/)
- **Lectra Diamino**: professional marker-making and automatic nesting that honors production constraints and mixes automatic nesting with interactive placement. — [Diamino (software.informer description)](https://diamino-v5r1.software.informer.com/) (secondary). Lectra's cloud cutting-room platform **Valia Fashion** launched October 2024 in the US, Canada and Europe and expanded to Mexico, Brazil and South America in May 2025. — [Textile World, May 2025](https://www.textileworld.com/textile-world/knitting-apparel/2025/05/lectra-continues-global-expansion-of-valia-fashion-to-new-key-markets/)
- Typical marker efficiency: "most well-optimized apparel styles land somewhere between 82 and 90 percent". Manufacturers expect more than 80%. A move from 85% to 87% can decide margin. Fabric is reported as 50–70% (another source: 40–60%) of garment cost. — [Apex Fashion Lab glossary](https://www.apexfashionlab.com/glossary/marker-making); [ScienceDirect: cut-and-sew waste, summer dress](https://www.sciencedirect.com/science/article/abs/pii/S0959652619340910); [Leeline Apparel](https://www.leelineapparel.com/fabric-cost-per-garment/) (snippets; the glossary and cost-share figures are secondary or blog sources)
- AAMA DXF carries **stripe reference (layer 9)** and **plaid reference (layer 10)** lines, which commercial nesters use for pattern matching. — secondary layer summaries (see question 3)

### Inferences
- Apparel constraints map to nesting parameters. Grain line means allowed orientations {0°, 180°} for one-way-nap fabrics (velvet, prints with direction) or just {0°} for strict nap. Mirrored pairs (left/right pieces) come from flipping. Strip width is the usable fabric width (e.g., 140–150 cm). The size ratio (e.g., S:1, M:2, L:2, XL:1) sets item quantities. sparrow's per-item discrete orientations and fixed strip width match this directly.
- Fabric consumption estimate = marker length ÷ number of garments in the marker, plus end allowances and a shrinkage/defect factor. A fast pre-nest estimate can use total piece area ÷ (fabric width × expected efficiency, e.g., 0.85). Both are easy to code. A real nest gives a much better number.
- Realistic quality: on garment benchmarks the open-source state of the art is at or above published academic results, but no head-to-head benchmark against Diamino or AccuNest was found. The safe claim is "good enough for estimating and small-batch cutting", not "beats Lectra". Plaid/stripe matching, notch-aware buffers, spreading/cutter files (e.g., Lectra or Gerber cutter formats) and fabric-defect handling are where commercial tools stay ahead.
- Vendor statements such as "AI marker making cuts waste 15%" (iFactory) are marketing and should not be cited as fact.

### Gaps
- No published comparison of open-source nesters (sparrow, Deepnest) against Lectra Diamino or Gerber AccuNest on the same apparel markers.
- sparrow's actual densities on the shirts and trousers instances were not retrieved (arXiv blocked).
- Whether sparrow/jagua-rs already supports mirrored pairs and grouped "bundles" natively was not confirmed.

## 5. AI for garment and pattern generation (2025–2026): research vs production

### Takeaway
Research has moved fast. Image or text to sewing pattern now works in papers (Sewformer, DressCode, ChatGarment, AIpparel, Design2GarmentCode, and 2026 work such as DressWild, latent flow matching at SIGGRAPH 2026, GarmentWeaver and TailorCoPilot). Most outputs are simulation-ready GarmentCode-style JSON for standard silhouettes. They are not factory-grade patterns with correct ease, seam allowances, notches and grading. Commercial tools (CLO AI Pattern Drafter beta, Style3D AI, Tailornova, Lectra Apogy launched Sept 2026) are real but are assistants inside 3D or PLM workflows. Production patterns still need a pattern maker and a physical toile.

### Cited Findings — research (not production)
- **NeuralTailor** reconstructs sewing pattern structure from 3D garment point clouds (SIGGRAPH 2022, Korosteleva). — [ResearchGate](https://www.researchgate.net/publication/362203329_NeuralTailor_reconstructing_sewing_pattern_structures_from_3D_point_clouds_of_garments)
- **Sewformer** ("Towards Garment Sewing Pattern Reconstruction from a Single Image", ACM TOG 2023) is a DETR-like model mapping 2D images to sewing patterns. — [ACM DL](https://dl.acm.org/doi/10.1145/3618319); description from [DressCode review](https://liner.com/review/dresscode-autoregressively-sewing-and-generating-garments-from-text-guidance)
- **DressCode** (2024) generates sewing patterns plus PBR textures from text using "SewingGPT", an autoregressive GPT-style model with text cross-attention. It reports fewer distorted panels and stitching errors than Sewformer. Code is on GitHub. — [DressCode (alphaXiv)](https://www.alphaxiv.org/abs/2401.16465); [DressCode GitHub](https://github.com/IHe-KaiI/DressCode)
- **ChatGarment** (CVPR 2025) fine-tunes LLaVA (open VLM) to take an image or text and output a JSON that GarmentCode decodes into a sewing pattern. It supports estimation, generation and editing. — [ChatGarment project](https://chatgarment.github.io/); [arXiv 2412.17811](https://arxiv.org/html/2412.17811v1)
- **AIpparel** (CVPR 2025 Highlight) is a 7B multimodal model fine-tuned from LLaVA-1.5-7B that generates and edits sewing patterns from images and text, outputting simulation-ready patterns. It is MIT-licensed, weights are on HuggingFace, it needs a CUDA 12.1 GPU, and it is trained on GarmentCodeData-Multimodal (GCD-MM, with text descriptions and editing instructions). — [AIpparel code GitHub](https://github.com/georgeNakayama/AIpparel-Code); [arXiv 2412.03937](https://arxiv.org/pdf/2412.03937)
- **Design2GarmentCode** (CVPR 2025) uses a pre-trained large multimodal model as a "design interpreter" and an LLM fine-tuned on GarmentCode snippets as a "program synthesizer". It generates **Python pattern programs** rather than raw JSON. — [CVPR 2025 paper](https://openaccess.thecvf.com/content/CVPR2025/papers/Zhou_Design2GarmentCode_Turning_Design_Concepts_to_Tangible_Garments_Through_Program_Synthesis_CVPR_2025_paper.pdf); [arXiv 2412.08603](https://arxiv.org/pdf/2412.08603)
- Other 2025 generative models: **GarmentDiffusion** (multimodal diffusion for sewing patterns, code on GitHub) and **GarmageNet**. — [GarmentDiffusion GitHub](https://github.com/Shenfu-Research/GarmentDiffusion); [GarmentDiffusion arXiv 2504.21476](https://arxiv.org/pdf/2504.21476); [GarmageNet arXiv 2504.01483](https://arxiv.org/html/2504.01483v2)
- 2026 papers (titles and abstracts from search, not read in full):
  - **DressWild** (arXiv 2602.16502, Feb 2026): a feed-forward pipeline that reconstructs physics-consistent 2D patterns and 3D garments from a single in-the-wild image, using VLMs to normalize pose. — [arXiv 2602.16502](https://arxiv.org/abs/2602.16502)
  - **Learning Sewing Patterns via Latent Flow Matching of Implicit Fields** (arXiv 2601.17740, SIGGRAPH 2026): image-to-pattern estimation, pattern completion and refitting. — [arXiv 2601.17740](https://arxiv.org/abs/2601.17740)
  - **GarmentWeaver** (arXiv 2608.30550, 31 Aug 2026): "schema-aware structured synthesis" of executable sewing patterns from sketches and text. — [arXiv 2608.30550](https://arxiv.org/abs/2608.30550)
  - **TailorCoPilot** (arXiv 2608.25462, Aug 2026): "agentic pattern making with version-controlled state tracking". Details not retrieved. — [arXiv 2608.25462](https://arxiv.org/pdf/2608.25462)
- Common denominator: ChatGarment, Design2GarmentCode and AIpparel all build on GarmentCode as the pattern representation, adding LLMs, LMMs or VLMs to the pipeline. — [search summary of the three papers](https://openaccess.thecvf.com/content/CVPR2025/papers/Zhou_Design2GarmentCode_Turning_Design_Concepts_to_Tangible_Garments_Through_Program_Synthesis_CVPR_2025_paper.pdf)

### Inferences
- **Production-ready today:** parametric drafting from measurements (FreeSewing, Seamly2D, GRAFIS, Tailornova), commercial 3D with AI assistants (CLO, Style3D, Lectra Apogy), and tech-pack document generation. **Research or prototype:** image or text to pattern (ChatGarment, AIpparel, Design2GarmentCode, DressWild, GarmentWeaver). These produce plausible panel layouts for common garment types in GarmentCode's design space, but not industrial patterns with house ease, seam allowances, notches, grading and fabric-specific corrections.
- The most practical AI use for "us" is the Design2GarmentCode idea done manually: a general LLM (Claude) writes or edits *parametric pattern code* from a description or sketch, and a human checks it. This works because the pattern stays in readable, editable code built on a trusted block, rather than coming from an opaque neural network.
- A tech pack is mostly structured documentation (flat sketches, POM table, BOM, construction notes, size spec). An LLM plus a template (HTML or PDF, or a spreadsheet) can generate a draft tech pack directly from the parametric model's measurements. That is low risk and high time saving, but the factory-facing details must be checked by a human.

## 6. 3D garment previews from code

### Takeaway
3D preview from code is feasible. GarmentCode includes a draping pipeline (pattern JSON onto a parametric body, with a GPU cloth simulator built on NVIDIA Warp). Blender has free Python add-ons for sewing 2D panels into cloth simulations. CLO exposes a Python API inside CLO for automation. Simulation fidelity is good for visualization but not a substitute for a physical toile.

### Cited Findings
- GarmentCode provides a script (`test_garment_sim.py`) that drapes a JSON sewing pattern on the neutral body and a GUI showing draped 3D models. The project maintains **NvidiaWarp-GarmentCode**, an extension of NVIDIA's Warp framework with cloth-simulation improvements. — [GarmentCode docs](https://github.com/maria-korosteleva/GarmentCode/blob/main/docs/Running_garmentcode.md); [NvidiaWarp-GarmentCode](https://github.com/maria-korosteleva/NvidiaWarp-GarmentCode)
- **CLO API**: CLO supports plug-ins as `.dll`, `.dylib` and **`.py`**. Python scripts run inside CLO (Python editor under the Edit menu, or drag-and-drop a `.py` file). The API includes automation scenarios such as `utility_api.AutoHang()`, simulation and rendering. A community **clo3d-mcp** project exposes CLO to AI agents through a C++ plugin TCP server. — [CLO API docs: Python](https://developer.clo3d.com/python.html); [Plug-in management](https://developer.clo3d.com/register.html); [CLO API/SDK guide PDF](https://clo3d.oss-cn-shanghai.aliyuncs.com/web/CLO_API/4_1_1/CLO%20API_SDK_GUIDE_20230313.pdf); [clo3d-mcp](https://glama.ai/mcp/servers/Lilbonner/clo3d-mcp) (snippets)
- Blender: free/open add-ons include **Cloth Lab** (patterns, sewing, named seams, garment extraction), **cloth_sewing**, **blender_clothing_tools** (helpers to build clothing from sewing patterns for Blender's cloth engine) and **Seams to Sewing Pattern** (mesh seams to cloth-sim-ready patterns, exportable for printing). **Garment Tool** is a paid add-on (2D Bézier panels sewn into a sim-ready mesh, Marvelous-Designer-like). — [Cloth Lab](https://github.com/dodohan0721/cloth-lab); [cloth_sewing](https://github.com/potocpav/cloth_sewing); [blender_clothing_tools](https://github.com/whyoh/blender_clothing_tools); [Seams to Sewing Pattern](https://blenderartists.org/t/seams-to-sewing-pattern-v-0-9-for-2-8-and-2-9/1248713); [Garment Tool docs](https://joseconseco.github.io/GarmentToolDocs/)

### Inferences
- The cheapest path for a 3D preview is to export the parametric pattern as GarmentCode JSON (or build it in pygarment directly) and drape it with GarmentCode's simulator. A GPU helps. Alternatively, export DXF and import into CLO, which the niece may have at university, then script repetitive steps with CLO's Python API.
- Simulated drape depends on fabric parameters (bending, stretch, weight). Without measured fabric data, 3D shows proportions and gross fit problems, not true fit.

### Gaps
- GPU and hardware requirements for GarmentCode simulation were not confirmed (AIpparel needs a CUDA GPU).
- Whether CLO's Python API can be run headless or outside the CLO GUI could not be verified (docs blocked).

## 7. Practical "what we could build" list, complexity and limits

### Takeaway
With an AI coding assistant, a motivated non-expert could build within weeks a useful personal toolkit: measurement table to graded block set (bodice, skirt, trousers) to DXF-AAMA plus tiled-PDF plus A0 PDF, with a nesting and fabric-consumption script and auto-generated tech-pack drafts. It would not replace Modaris in a factory. Fit validation (toile), house standards, interoperability testing and pattern-making judgment remain human.

### Cited Findings (building blocks to reuse)
- Parametric engine: FreeSewing (JS, MIT, tiled PDF A4–A0) — [freesewing.dev](https://freesewing.dev/reference/api/); GarmentCode/pygarment (Python, MIT, JSON plus 3D drape) — [GitHub](https://github.com/maria-korosteleva/GarmentCode)
- DXF-AAMA/ASTM writing: ezdxf plus the `gerber_D6673` add-on — [ezdxf #789](https://github.com/mozman/ezdxf/discussions/789)
- PDF tiling/stitching: PDFStitcher (MPL-2.0) — [GitHub](https://github.com/Quinn-D/sewingutils)
- Nesting: sparrow (Rust, MIT) with the `spyrrow` Python wrapper, or sparrowstudio.app in the browser — [GitHub](https://github.com/JeroenGar/sparrow); pynest2d (LGPL) — [GitHub](https://github.com/Ultimaker/pynest2d); Deepnest — [GitHub](https://github.com/deepnest-next/deepnest)
- 3D: GarmentCode simulator; CLO Python API; Blender add-ons (see question 6)
- AI pattern generation (experimental): ChatGarment, AIpparel (weights on HuggingFace), Design2GarmentCode — see question 5

### Inferences (complexity estimates are the researcher's judgment, not sourced)
| Tool | What it does | Effort with AI assistant | Main risks / limits |
|---|---|---|---|
| A. Measurement-table drafter (Python) | Encodes the school's method (e.g., Secoli/Burgo/Aldrich) for bodice, skirt, trousers, sleeve. Input: CSV or Excel of sizes or one person's measurements. Output: SVG preview | 1–3 weeks for 3–4 blocks (formulas must be transcribed from the course book and checked by the niece) | Formula transcription errors, ease values, curve quality (armhole, crotch). Needs checking against her hand drafts |
| B. Seam allowance plus notches plus grain plus labels | Offset curves (shapely `buffer` or a proper offset with corner treatment: mitred, squared-off at hems), notch marks at matched points, grain line, piece name/size/quantity | 3–7 days | Corner handling at seam junctions (the "turn-back" angle at hems) is fiddly. Notch types (V, T, slit) vary by target CAD |
| C. Grading | Either re-draft per size (simple) or grade-point x/y rules. Export a nested size stack | 2–5 days | Grade increments are brand know-how. RUL export format unverified |
| D. DXF-AAMA export | ezdxf: one block per piece, layers 1/4/7/8/14, text tags. Optional ASTM via the `gerber_D6673` add-on | 3–10 days including import testing | Must be tested in Modaris, CLO and AccuMark. Graded DXF plus RUL into Modaris is the least certain part |
| E. PDF outputs | A4/Letter tiled with overlap, marks and a test square. A0 single sheet or roll-width plotter PDF, with layers per size | 2–4 days (or reuse FreeSewing or PDFStitcher) | Printer scaling errors (user must print at 100%) |
| F. Nesting plus consumption calculator | Feed pieces plus quantities, fabric width, allowed rotations (0/180), flips to sparrow or spyrrow. Report marker length, efficiency and consumption per garment | 1–2 weeks | No plaid/stripe matching unless custom-coded. No cutter-file output. Results not benchmarked against Diamino |
| G. Tech-pack generator | LLM plus template turns the parametric model (measurements, POM, BOM inputs) into a PDF or Excel tech pack with flats exported from the pattern | 3–7 days | Construction details and tolerances need expert review |
| H. Web app | Wraps A–G in a browser UI (FreeSewing-style JS, or Python backend with a JS front end) | 2–6 weeks | Scope creep. Hosting is optional |
| I. AI "describe/sketch to pattern" | Claude edits the parametric code from a text or sketch description. Optionally try ChatGarment or AIpparel locally on a GPU | Days for LLM-edits-code; weeks for research models | Research models give approximate, GarmentCode-space patterns only, not production patterns |

- **Realistic limits to state plainly:**
  1. Fit is validated only by sewing a toile (tela di prova) on a real body or form and correcting. Code and 3D simulation do not remove this.
  2. Fabric behavior (stretch, drape, shrinkage, bias) changes ease and grading. This needs expert judgment or measured fabric parameters.
  3. Industrial standards (seam allowance per operation, notch conventions, house grading tables, cutting-room formats) vary by company. A home-built tool must be adapted to each.
  4. Interoperability with Modaris is plausible via DXF-AAMA but must be tested. Lectra's own ecosystem (Modaris, Diamino, Valia, and now Apogy with AI agents) stays more integrated.
  5. For a fashion student, the value is learning plus speed: automating repetitive drafting, grading, printing and estimating. It does not replace Modaris skills, which employers expect. Secoli still teaches Modaris V2025.2.

### Gaps
- No sourced effort or time benchmarks exist for building such tools. The table's estimates are judgment.
- No test was done of DXF import into Modaris, AccuMark or CLO from ezdxf output.
- No source compares the cost of Modaris/Diamino licenses with open-source alternatives (pricing not public).
